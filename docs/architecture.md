# 运行时设计

## 分层

`contracts.py` 定义请求、风险、意图、资料和回答契约。`runtime.py` 连接各阶段；风险分支绕过模型、检索和存储。常规请求由 `classification.py` 并行获取语义向量与模型分类，再与关键词分数融合。

角色范围先由意图确定，实例再按最近40次调用的成功率和平均延迟选择。显式复合请求可以添加辅助角色并行运行。专业角色失败只重试同角色实例，不自动跨专业切换。汇总失败返回已验证的主角色结果，并标记降级。

## 工具与检索

`execution.py` 控制角色工具白名单、参数验证、知识域、超时及熔断。连续两次工具失败进入冷却；到期只允许一个探测调用。角色使用服务商原生工具调用，最多三轮模型交互；药品、报告和就医准备任务必须先查资料。

`retrieval.py` 使用查询压缩、词法和向量并行召回、可选模型重排及90秒哈希键缓存。审批状态与知识域同时过滤。稳定资料标识以 upsert 替换，更新清空缓存。模型只可引用本次工具实际返回的标识；草稿和凭空引用不通过校验。

## 记忆与上下文

用户、会话及咨询对象经 SHA-256 组成存储作用域。Redis 保留24小时会话；12条消息触发摘要，保留最后4条原始消息，摘要写入独立 Chroma collection。摘要检索限定同一作用域，没有跨用户画像推断。

按需模式选择最近4条历史、摘要和本角色检索证据；全量模式增加可用历史与本角色公开资料，工具权限不扩大。提示词中的历史和资料仅为数据，不能更改角色权限。

## 观测与评测

每次请求有独立 ContextVar 日志，记录阶段、候选分数、实例、工具状态、引用标识和服务商用量；不记录原始咨询或工具参数值。追踪在内存最多保留256条。未知用量返回 null，不用字符数伪装 Token。

评测逐项调用相同运行时，检查角色、风险、引用、降级和虚构操作，再运行四维 Judge。Judge 失败单独记录为未通过。小规模虚构集与规则校验不证明医学准确性。
